## Commands

```bash
./tools/build_ios.sh Debug > /tmp/ios.log 2>&1; grep -E 'BUILD (SUCCEEDED|FAILED)| error:' /tmp/ios.log
APP=build-ios/Debug-iphoneos/CalaosHome.app
xcrun devicectl list devices
xcrun devicectl device install app --device 00008130-000955AE1EE3803A "$APP"
xcrun devicectl device process launch --terminate-existing --device 00008130-000955AE1EE3803A fr.calaos.CalaosMobile
./tools/build_ios.sh Release --archive          # archive, no upload
```

Simulators: `xcrun simctl list devices available`, `xcrun simctl boot <udid>`, `xcrun simctl install booted <app>`, `xcrun simctl launch booted fr.calaos.CalaosMobile`, `xcrun simctl io booted screenshot /tmp/x.png`. A simulator build needs simulator slices in the Qt kit (check `lipo -info`/`vtool` on a Qt framework binary) and `CMAKE_OSX_SYSROOT=iphonesimulator`; use a separate build dir (e.g. `build-ios-sim/`) so the device build cache is not clobbered.

## Pitfalls

1. After an Xcode update, configure fails with missing Qt modules / stale SDK paths: delete `build-ios/CMakeCache.txt` and `build-ios/CMakeFiles`.
2. CMake 4 needs `-DCMAKE_POLICY_VERSION_MINIMUM=3.5` (3rd_party/quickflux) — already in the script.
3. The Xcode project is generated by CMake: never hand-edit it; put settings in `cmake/iOS.cmake` / `ios/CMakeLists.txt` (`XCODE_ATTRIBUTE_*`, resources).
4. Resources that must land in the bundle (privacy manifest, storyboard, asset catalog) must be listed as target sources/resources in CMake; verify with `find build-ios/Debug-iphoneos/CalaosHome.app` (and `PlugIns/PushNotif.appex`).
5. Signing errors mentioning the Program License Agreement mean the Apple developer account must accept a new agreement on developer.apple.com — only the user can do that.
6. The extension must not link Qt.
7. Do not log credentials or push tokens.
